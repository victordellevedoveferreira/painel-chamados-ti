# Antes de publicar

Este repositório é uma base de referência. Victor deve executar, estudar e personalizar o projeto antes de apresentá-lo em processos seletivos.

## Checklist obrigatório

- [ ] Executar o pipeline e os testes no próprio computador.
- [ ] Ler e explicar cada transformação de `src/etl.py`.
- [ ] Abrir o banco SQLite e executar as consultas de `src/sql/analytics.sql`.
- [ ] Trocar pelo menos uma regra, gráfico ou indicador com decisão própria.
- [ ] Criar uma captura atualizada do dashboard.
- [ ] Publicar o dashboard com GitHub Pages.
- [ ] Fazer commits pequenos e descritivos, sem enviar tudo como "projeto final".
- [ ] Fixar o repositório no perfil do GitHub.
- [ ] Nunca publicar dados reais do estágio.

## Perguntas que ele deve conseguir responder

1. Por que chamados abertos não entram no cálculo de tempo médio?
2. Como o projeto identifica o cumprimento de SLA?
3. O que acontece quando a data de abertura é inválida?
4. Por que SQLite foi escolhido?
5. Como o pipeline poderia receber dados incrementais?
6. Qual indicador ajudaria uma coordenação de suporte a tomar uma decisão?
